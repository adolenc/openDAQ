# C bindings

`include/` and `src/` hold a thin C wrapper around the openDAQ C++ API: an opaque handle
`typedef struct daq<Type> daq<Type>;` per interface, one `daq<Type>_<method>(self, ...)` function per
interface method, and `daq<Type>_<factory>(...)` constructors. Every wrapper casts the handle back to
the C++ interface and forwards the call, so the C bindings add no behaviour of their own.

The bindings are **generated** from the core C++ headers. There is no list of interfaces to
maintain: the generator finds every header that declares an interface or a factory, so a new
interface in the core shows up here the next time the generator runs.

```sh
../regenerate.sh        # rebuilds the generators from source, then regenerates (needs mono + mcs)
./run_rtgen.sh          # only regenerates, with the committed RTGen.C.dll (needs mono)
```

`../json/opendaq.json` describes this C API in machine-readable form: exactly what the library
exports, under the same names. `../json/check_c_bindings.py` verifies that the two agree; run it
after regenerating.

## What is generated, and how it is named

| C++ | C | Example |
| --- | --- | --- |
| interface `IFoo` | opaque handle `daqFoo` | `IStreamReader` → `daqStreamReader` |
| its interface id | `DAQ_FOO_INTF_ID`, `daqFoo_getInterfaceId(daqIntfID*)` | `daqStreamReader_getInterfaceId` |
| method `IFoo::bar(args)` | `daqFoo_bar(daqFoo* self, args)` | `daqStreamReader_read` |
| factory `createBar` of `IFoo` | `daqFoo_createBar(daqFoo** obj, args)` | `daqStreamReader_createStreamReaderFromPort` |
| function `daqBar` in the header of `IFoo` | `daqFoo_bar(args)` | `daqSetErrorInfo` → `daqErrorInfo_setErrorInfo` |
| enum `Foo`, option `Bar` | `daqFoo`, `daqFooBar` | `daqSampleTypeFloat64` |
| status code `OPENDAQ_ERR_FOO` | `DAQ_ERR_FOO` | `DAQ_ERR_NOTFOUND` |

Types in signatures: an interface pointer keeps its number of `*`; the aliases of C fundamental
types are prefixed `daqC` (`daqCBool`, `daqCInt`, `daqCFloat`, `daqCSizeT`, `daqCConstCharPtr`, ...)
so that they cannot collide with an interface of the same name (`Float` / `IFloat`); every other
value type and enum is prefixed `daq` (`daqErrCode`, `daqIntfID`, `daqSampleType`). A const reference
to a value type (`const IntfID&`) is passed by value. Callbacks (`daqFuncCall`, `daqProcCall`,
`daqEventCall`) take opaque handles.

Two enums keep enumerators without the enum name in them: `daqCCoreType` (`daqCtBool`, ...; its C++
options already carry the `ct` prefix) and `daqLockingStrategy` (`daqOwnLock`, ...).

The rules live in one place,
[`RTGen.Shared/CBindingRules.cs`](../../shared/tools/RTGen/src/project/RTGen.Shared/CBindingRules.cs),
which is compiled into both the C generator and the JSON generator, so that the JSON describes the
C API under the names the C generator gives it.

### Files

| | |
| --- | --- |
| `include/<library>/<header>.h`, `src/<library>/<header>.cpp` | generated, one pair per core header |
| `include/cenums.h` | generated, every enum the API uses |
| `include/cerrors.h` | generated, every status code |
| `include/copendaq.h` | generated umbrella header |
| `include/ccommon.h` | hand-written: the ABI types (`daqErrCode`, `daqCBool`, `daqIntfID`, the callbacks, ...) |
| `include/ccoretypes/base_object.h` | hand-written: `IUnknown` and `IBaseObject` (see below) |
| `include/ccoretypes/factories.h` | hand-written: six factories (see below) |
| `include/private/`, `include/copendaq_private.h`, `src/private/` | hand-written implementation helpers |

Generated files carry an `<auto-generated>` banner. A generated file whose core header disappears is
removed by the next run.

## What was added to make the bindings complete

The bindings used to be generated from a list of headers kept by hand in `run_rtgen.sh` and
`CMakeLists.txt`, with a number of files then corrected by hand. Relative to that state (upstream
`main`), the C API grew from 1730 to 1835 functions. Everything below is now produced by the
generator unless marked hand-written.

**Interfaces that were not on the list** and are now discovered automatically:
`IMutex`, `IPropertyMetadataReadArgs`, `IPropertyObjectCore`, `IDevelopmentVersionInfo`,
`IErrorGuard`, `IWeakRef` and `ISupportsWeakRef`, `IWorkRepetitive`, `IWrappedDataPacket`,
`IMirroredInputPortPrivate`, `ISyncInterfaceInternal`, `ISynchronizationPrivate`, `IPacketBuffer`,
`IPacketBufferBuilder`; and methods added to already bound interfaces after their file was last
regenerated (`IContextInternal::setRootDevice`, `IConnectionInternal::closeQueue`,
`ILoggerComponent::logMessage`, `IComplexNumber::getValue` / `equalsValue`, the `IErrorInfo` error
code accessors, `IInspectable::getInterfaceIds`).

**Headers the generator could not parse**, which silently kept whatever had been generated last.
They are now parsed through the sanitizer shared with the JSON generator:

- `daq<Type>_getInterfaceId` for `IFunction`, `IProcedure`, `ISerializer`, `IDeserializer`,
  `IErrorInfo`, `ILoggerSink`, `ICoreType`, `IPropertyValueEventArgs`
- factory-only headers, never emitted before:
  `daqDeserializer_createJsonDeserializer`, `daqList_createOwningList`, `daqDict_createOwningDict`,
  the 11 `daqCoreEventArgs_createCoreEventArgs*` factories,
  `daqDataPacket_createBinaryDataPacket` / `...WithExternalMemory`,
  `daqSearchFilter_createVisiblePropertyFilter` / `createReadOnlyPropertyFilter` /
  `createNamePropertyFilter`

**Headers with a factory under a preprocessor conditional** (`logger_sink.h`, `allocator.h`) are
generated like any other; they used to be kept as hand-corrected copies, which is why
`daqLoggerSink_getInterfaceId` was missing. The conditional factories themselves are left out, see
below.

**Freestanding functions** of the core are wrapped: the thread error info functions
(`daqErrorInfo_setErrorInfo`, `extendErrorInfo`, `getErrorInfo`, `getErrorInfoList`,
`clearErrorInfo`, `getErrorInfoMessage`) and `daqDeserializer_unregisterSerializerFactory`.

**Enums and status codes** are generated into `cenums.h` and `cerrors.h` instead of being copied by
hand into a `common.h` and an `errors.h` per library. The copies had fallen behind the core: this
added `daqPacketReadyNotificationUnspecified`, `DAQ_ERR_NOT_CLONEABLE` and `DAQ_PARTIAL_SUCCESS`, and
corrected the `daqPropertyEventType` enumerators.

**Hand-written additions**, for the parts that stay hand-written:
`daqUnknown_getInterfaceId`, `daqBaseObject_getInterfaceId` and
`daqSerializer_createJsonSerializerWithVersion`.

### Renamed along the way

Names that did not follow the rules above were brought in line, which changes them for existing C
code:

| Before | Now |
| --- | --- |
| `daqBool`, `daqInt`, `daqUInt`, `daqFloat`, `daqSizeT`, `daqCharPtr`, `daqConstCharPtr`, `daqVoidPtr`, `daqEnumType`, `daqCoreType` (the enum) | `daqCBool`, `daqCInt`, `daqCUInt`, `daqCFloat`, `daqCSizeT`, `daqCCharPtr`, `daqCConstCharPtr`, `daqCVoidPtr`, `daqCEnumType`, `daqCCoreType` |
| `True`, `False` | `daqTrue`, `daqFalse` |
| `daqFloatObject` and `daqFloatObject_*` | `daqFloat` and `daqFloat_*` |
| `daqBaseObject_addRef`, `daqBaseObject_releaseRef`, `daqBaseObject_queryInterface` | `daqUnknown_addRef`, `daqUnknown_releaseRef`, `daqUnknown_queryInterface` |
| `daqBaseObject_create` | `daqBaseObject_createBaseObject` |
| `daqPropertyEventTypeEventTypeUpdate` / `Clear` / `Read` | `daqPropertyEventTypeUpdate` / `Clear` / `Read` |
| `<ccoretypes/errors.h>`, `<copendaq/*/common.h>`, `<copendaq/*/*_errors.h>` | `<cerrors.h>`, `<cenums.h>` (both included by `<ccommon.h>`) |

`DAQ_ERRTYPE_*`, `DAQ_MAKE_ERROR` and `DAQ_LOG_LEVEL_*` are gone: the status codes are spelled out
and the log levels are the `daqLogLevel` enum.

## What is not in the C bindings, and why

The C API is the C++ API minus the following. `opendaq.json` does not describe them either.

**Six internal interfaces** (`UnboundHeaders` in `CBindingRules.cs`):

| Interface | Reason |
| --- | --- |
| `ILoggerSinkBasePrivate` | returns a spdlog `SinkPtr` |
| `ILoggerThreadPoolPrivate` | returns a spdlog `ThreadPoolPtr` |
| `ITaskInternal` | returns Taskflow's `tf::Task` and `tf::Taskflow` by value |
| `IStreamingPrivate` | takes C++ smart pointers (`StringPtr`, `DevicePtr`) by reference |
| `IDataRuleCalcPrivate` | takes a `NumberPtr` reference; also overloaded |
| `IScalingCalcPrivate` | two `scaleData` overloads, which would map to the same C function. Upstream had named the second one `scaleDataOutput` by hand; it is left out until overloads get a naming rule. |

**Two functions**: `daqRegisterSerializerFactory` and `daqGetSerializerFactory` take
`daqDeserializerFactory`, a C++ function pointer type with no C declaration.

**Two factories declared under a preprocessor conditional**: `createWinDebugLoggerSink`
(`#ifdef _WIN32`) and `createMiMallocAllocator` (`#ifdef OPENDAQ_MIMALLOC_SUPPORT`) only exist in
some builds of the core. They are left out, so that the C bindings export the same functions on
every platform and in every configuration. (Upstream declared the first under `#ifdef _WIN32` by
hand and had the second commented out.) The generator finds such factories by itself
(`RTGen.Shared/PreprocessorConditions.cs`).

**C++ conveniences with no ABI of their own**: templates, smart pointers and inline helpers are not
part of the exported API and have nothing to bind.

## What is written by hand, and why

- **`ccommon.h`**: the ABI types. They mirror `coretypes/common.h` and change about as often as the
  ABI does. The JSON generator reads them off this header into the `types` section of
  `opendaq.json`, so a typedef added here is described there without further ado.
- **`ccoretypes/base_object.h`**: `IUnknown` (`queryInterface`, `addRef`, `releaseRef`) and
  `IBaseObject` (`borrowInterface`, `dispose`, `getHashCode`, `equals`, `toString`,
  `createBaseObject`). Their names follow the rules, but the header adds inline conveniences
  (`daqAddRef`, `daqReleaseRef`, `DAQ_QUERY_INTERFACE`, ...), and two declarations deliberately
  differ from a mechanical translation: `queryInterface` and `borrowInterface` return the object
  through a typed `daqBaseObject** interfacePtr` where C++ has an untyped `void** obj`. Those two
  are listed in `CBindingRules.HandWrittenArguments`, so that the JSON describes them as declared.
- **`ccoretypes/factories.h`**:
  - `daqEventHandler_createEventHandler` adapts a C callback to `IEventHandler`
    (`private/c_event_handler_impl.h`). C++ builds event handlers from templates, so there is no
    exported function to wrap. It is listed in `CBindingRules.HandWrittenFactories` so that the JSON
    describes it.
  - `daqFunction_createFunctionWithData`, `daqProcedure_createProcedureWithData` and
    `daqEventHandler_createEventHandlerWithData` take a callback that also gets a `void* userData`,
    and a `daqFreeUserData` that the object calls with `userData` when it is destroyed. They let a
    binding route calls to its own closures without a separate C function per closure. They are
    listed in `CBindingRules.HandWrittenFactories` as well.
  - `daqSerializer_createJsonSerializer` and `daqSerializer_createJsonSerializerWithVersion`: the
    core declares these as plain functions in a header without an interface, which the C generator
    does not visit. A new factory of that kind has to be added here by hand;
    `check_c_bindings.py` fails until it is.

## Changing the generator

The generator is `shared/tools/RTGen/src/project/RTGen.C/`:

- `CBatchGeneration.cs` finds the headers, prunes files that are no longer generated and writes the
  umbrella header.
- `Generators/CGenerator.cs` emits one header/source pair per core header from `Templates/`.
- `CTreeHeaders.cs` emits `cenums.h` and `cerrors.h` from the linked API description (the model
  builder of `RTGen.Json`, which `RTGen.C.dll` compiles in).
- `../RTGen.Shared/` is compiled into both generators: the header sanitizer, the preprocessor
  condition scanner and the naming rules.

`rtgen.exe` loads the committed `bin/RTGen.C.dll` and reads the templates in `bin/Templates/`, so
after changing a source or a template run `../regenerate.sh`, which rebuilds the binary, copies the
templates and regenerates. Commit the rebuilt binary together with the regenerated bindings.

## Building and testing

Configure with `-DOPENDAQ_GENERATE_C_BINDINGS=ON` (target `copendaq`). The tests need
`-DOPENDAQ_ENABLE_TESTS=ON`: `test_ccoretypes`, `test_ccoreobjects`, `test_copendaq_*`, and the pure C
`test_c_compile_and_run`, which compiles the umbrella header as C.
